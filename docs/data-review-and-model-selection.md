# 학생 데이터 전처리와 모델 설정 선정 계획

작성: 2026-10-27 · 상태: 전처리 화면·주행 단위 분리·Orange 파일 내보내기 구현 및 검증. 아래 모델 후보 학습·평가 도구와 시나리오 계열 분리는 아직 미구현. 사용법·검증 범위는 `simulator/PREPROCESSING.md` 참고.

## 1. 기존 실험의 범위와 수정 사항

`comparison.csv`는 모델 이식 전후 예측을 비교한 증거 파일이며 학생 학습용 CSV가 아니다. 긴 소수는 무작위 입력 및 분기 경계 시험에서 의도적으로 유지했다. 반올림하면 임계값 바로 전후의 차이를 잃을 수 있다. 화면 표시만 반올림한다.

합성 목표값은 임의의 규칙으로 만들었다. 정지 상태에서 음수 변화량이 있는 등 실제 주행 기록으로 불가능한 조합도 있다. 모델 연결 시험에는 사용할 수 있지만, 주행·안전성 평가나 수업용 하이퍼파라미터 선정에는 사용할 수 없다. 노면 속도 상한을 넘는 시험 입력도 실제 주행 수집 데이터와 구별한다.

`max_depth=5`, `min_samples_leaf=2`, `min_samples_split=4`는 연결 시험용 설정일 뿐 평가로 선정한 값이 아니다. 코드에서 CONNECTION_TEST_PARAMS로 명명하여 수업 기본값과 구분한다. 수업용 설정은 미정으로 유지한다.

predict.mjs는 예측 시 잘못된 노면, 누락/비수치/무한대, 음수 속도·거리를 거부한다. 별도로 구현한 simulator/review.mjs는 학생 CSV의 오류·결측치와 물리적으로 불가능한 실제 변화량을 탐지한다. 수정은 학생 판단과 이유가 있어야 반영하며, 예측 입력 검사를 전처리 완료로 표현하지 않는다.

## 2. 자동 탐지와 학생 판단의 역할

### 학생에게 반드시 설명할 개념

- **결측치:** 있어야 할 값이 빠진 기록이다. 예를 들어 노면이나 속도 칸이 비어 있는 경우다. 숫자 0은 값이 있으므로 결측치와 다르다. 원본에서 복구할 수 있는지 확인하고, 근거 없이 평균이나 0으로 채우지 않는다.
- **이상치:** 다른 기록과 크게 다르거나 예상 범위를 벗어나 확인이 필요한 값이다. 예를 들어 주변 기록보다 매우 큰 감속량이 있다. 입력·저장 오류일 수도 있지만 실제 급감속 장면일 수도 있으므로, 이상치라는 이유만으로 삭제하지 않는다. 물리적으로 불가능한 값과 드물지만 가능한 관측을 구분한다.

전처리 화면과 교사 안내에 두 용어·뜻·예시를 명시한다. 학생은 대표 사례에서 '결측치인가, 이상치 후보인가, 정상 기록인가 → 근거는 무엇인가 → 어떻게 처리했는가'를 설명한다. 실제 수집 자료에 사례가 없으면 별도 연습 자료임을 밝히고 두 개념을 다룬다. 통계적 이상치 기준은 자동 삭제 기준이 아니라 확인 후보를 찾는 도구로 소개한다.

원칙: 프로그램은 문제를 찾아 설명하고, 학생은 근거를 보고 유지·수정·제외를 결정한다. 원본은 보존한다. 조용히 삭제하거나 평균으로 채우지 않는다.

| 상황 | 프로그램이 할 일 | 학생이 할 일 |
| --- | --- | --- |
| 빈칸, 숫자 칸의 문자, 알 수 없는 노면 | 해당 셀과 이유 표시, 해결 전 학습 내보내기 차단 | 원본 기록 확인 후 근거 있는 복구 또는 제외 |
| 단위·노면 표기 불일치 | 변환 후보 및 전후 값 제시 | 단위·의미 확인 후 적용 승인 |
| 음수 속도, 해당 설정의 속도 상한 초과 | 주행 설정 버전과 함께 오류 후보 표시 | 설정/기록 출처 확인; 임의로 0이나 상한으로 자르지 않음 |
| 실제 변화량이 제동·가속 한계 밖 | 같은 주행의 설정과 1초 시작/종료 속도를 비교 | 기록 시점·단위 오류인지 확인 후 처리 |
| 1초가 안 된 충돌·종료 구간 | 부분 구간으로 표시하고 1초 학습 내보내기에서 제외 | 이유를 확인하고 분석 기록으로 보존 |
| 같은 run_id·시각의 중복 행 | 저장 중복 후보 표시 | 중복인지 확인해 하나 유지; 제외 근거 기록 |
| 다른 시각에 동일한 입력·목표값 | 정상 반복일 수 있음을 표시 | 정속·정지 등 상황 확인, 자동 삭제하지 않음 |
| 모둠 원칙과 다른 실제 운전 | 오류로 단정하지 않음 | 선택 이유·운전 실수 여부를 기록하고 포함 여부 설명 |
| 드문 급감속·충돌 직전 기록 | 희귀하다는 이유로 이상치 삭제하지 않음 | 문제 장면인지 확인; 안전 학습에 중요한 기록일 수 있음 |
| 마른 노면·먼 거리 기록에 치우침 | 학습 자료의 조건별 개수 표시 | 부족한 조건을 새로 운전해 보완 |

감속 한계 밖인지 검사하는 대상은 학생 시범 기록의 **실제 변화량**이다. 모델의 **제안값**이 한계를 넘는 것은 별도 분석 대상이며, 수집 오류와 혼동하지 않는다.
`v_end = v_start + actual_delta`가 해당 주행의 속도 범위 안인지 확인하고, 1초 물리 계산의 가능한 변화량과 비교한다. 정확한 물리 검사 규칙은 주행 코어와 같은 설정을 사용한다.
자동으로 기록되는 정상 데이터에 교육 목적으로 오류를 몰래 넣지 않는다. 실제 오류가 없다면 별도 '오류 찾기 연습 데이터'임을 표시한 자료로 결측·중복·단위 오류를 연습한다.

## 3. 학생 전처리 화면 및 산출물

흐름: 원본 보기 → 문제 후보 선택 → 해당 주행 장면/기록 확인 → 유지·수정·제외와 이유 작성 → 전후 비교 → 학습용 파일 내보내기.

화면에는 행 ID, 주행·시각, 원본 값, 문제 종류, 처리 방법, 변경 값, 이유, 처리 상태를 표시한다. 수정은 원본을 덮어쓰지 않고 별도의 변경 기록으로 저장하며 취소할 수 있다.
불명확한 실제 측정값을 학생이 추측해서 채우지 않는다. 복구 근거가 없으면 해당 행을 학습에서 제외하고 필요하면 새 주행으로 보완한다. 제외된 행도 원본과 검토표에는 남긴다.
내보내기 전 '원본 N행 → 수정 M행 / 제외 K행 → 최종 L행'과 사유를 확인한다. 동일 입력·동일 목표가 반복된 정상 행은 유지될 수 있다.

산출물:
- raw: 변하지 않은 주행 원본과 설정 버전.
- review: 행 ID, 분류, 유지/수정/제외, 이전/이후 값, 근거, 처리 이력.
- cleaned: 승인된 수정과 제외를 반영한 별도 학습 자료.
- split: 주행별 학습·검증 배정과 자료 버전.
- preprocessing-summary: 대표 처리 1건의 이유 및 조건별 분포 전후 비교.

2차시의 기존 5분은 긴 전처리 강의를 포함하기 어렵다. 프로그램이 후보를 요약하고 학생은 대표 1–2건의 근거를 설명하도록 첫 운영안을 잡는다. 실제 시범 운영에서 부족하면 수업 시간을 재배분하며 전처리 활동을 생략하지 않는다.

## 4. 데이터 누출을 막는 분리

주행 ID 단위로 학습·검증을 먼저 배정하고, 같은 원본 주행에서 잘라낸 구간이나 복제·수정 행도 같은 집합에 둔다. 동일 시나리오 반복 주행에 대한 일반화를 확인할 때는 시나리오 계열도 묶어서 분리한다. 무작위 행 분리는 사용하지 않는다.
형식·단위·물리 오류 규칙은 예측 결과를 보기 전에 정하고 양쪽에 동일하게 적용한다. 검증 오차가 큰 행을 이유 없이 제외해서 성능을 높이지 않는다. 결측값 대체 등 데이터에서 통계를 학습하는 변환을 나중에 추가하면 학습 자료에서만 추정한다.
학습/검증 양쪽의 유효 주행 수와 제외 내역을 보고한다. 독립 주행이 부족하면 더 수집하며, 행 수만 많다는 이유로 검증이 충분하다고 판단하지 않는다.

## 5. 하이퍼파라미터의 의미와 후보

Orange 설치 버전의 TreeLearner 소스 기준:
- max_depth: 트리 최대 깊이 제한. 복잡한 분기와 학생 해석 난이도에 영향을 준다.
- min_samples_leaf: 끝마디에 필요한 최소 기록 수. 소수 기록만 따라가는 정도에 영향을 준다.
- min_samples_split: 한 마디를 더 나누기 위해 필요한 최소 기록 수. '4개로 나눈다' 또는 '4번 나눈다'는 뜻이 아니다. 기준을 만족해도 분할이 보장되는 것은 아니다.

교사 사전 실험의 후보 초안:
- max_depth: 2, 3, 4, 5, 6
- min_samples_leaf: 2, 5, 10
- min_samples_split: 4, 10, 20

이는 최대 45조합의 출발점이며 최종값이 아니다. 실제 유효 데이터 수·주행 수와 후보 간 중복 효과를 확인해 탐색 범위를 조정하고 사유를 기록한다. 학습 시간이 아니라 적절한 독립 데이터 확보가 선행 조건이다.

## 6. 선정 실험과 평가 기준

1. 실제 시뮬레이터에서 교사/시범 학생의 정상 주행 기록을 수집한다. 감속·정지·재출발, 두 노면, 거리·속도 조건을 포함한다.
2. 검토 완료 데이터 버전을 고정하고 학습/튜닝 검증/최종 확인 자료를 주행 또는 시나리오 계열 단위로 구분한다. 자료가 충분하면 개발 자료 안에서 그룹 교차검증을 수행한다.
3. 모든 후보에 같은 분할과 전처리 규칙을 적용하여 학습한다. 학습 자료의 평균 변화량을 출력하는 단순 기준 모델과도 비교한다.
4. 후보별 MAE, RMSE와 노면·감속/정지/재출발 조건별 오차, 실제 깊이·끝마디 수를 기록한다. 주행별 점수를 함께 보고해 긴 주행 하나가 평균을 지배하지 않도록 한다.
5. 튜닝용 코스에서 반복 자동 주행해 충돌률, 기준 위반 비율/시간, 완주율·시간, 재출발 실패를 평가한다. 같은 코스·물리 설정·초기 조건으로 비교한다.
6. 수업에 사용할 후보는 예측 오차와 주행 결과, 학생이 대표 경로를 설명할 수 있는 복잡도를 함께 보고 선정한다. 사전에 정한 주행 허용 조건을 통과한 후보 중 오차·복잡도를 비교하며, 적합한 후보가 없으면 데이터/과제를 개선한다.
7. 선정 후 설정·자료·분할·코스·전처리·변환기 버전 및 선택 이유를 저장한다. 최종 확인 자료는 이때 한 번 평가하고 다시 튜닝에 사용하지 않는다.

MAE/RMSE는 학생 운전 기록을 얼마나 비슷하게 예측하는지 보여준다. 학생 기록 자체가 안전하지 않을 수 있으므로, 낮은 예측 오차를 안전한 주행의 증거로 사용하지 않는다. 주행 허용 수치와 복잡도 기준은 코스/학생 시범 운영 전 별도로 정하며 현재 확정하지 않는다.

노션의 A 코스는 학생 개선에 쓰는 코스이고 B는 최종 확인 코스다. 교사의 하이퍼파라미터 탐색에는 별도 개발·튜닝 코스를 사용하고 B를 탐색 도구에 넣지 않는다. 최종 확인 결과로 재설계했다면 그 자료는 더 이상 미공개 시험 자료가 아니므로 새 최종 자료가 필요하다.

## 7. 수업 운영과 개발 순서

교사는 사전 실험으로 기본 설정을 선정한다. 학생은 전처리와 기록 개선을 직접 수행한다. 2–3차시에서 데이터 보완 효과를 비교할 때는 하이퍼파라미터를 동일하게 유지한다. 설정 변화도 학습 목표에 넣는다면 별도 확장 활동으로 한 번에 한 설정만 바꾸고, 데이터 변경 실험과 구분한다.

구현 순서: 주행 코어·수집 → 오류 탐지 및 학생 검토 화면 → 주행 단위 분리 → 후보 학습·평가 도구 → 주행 평가 → 교사 설정 선정 → 수업 시범 운영.
지금 합성 데이터에 후보를 많이 돌려 최적 설정을 발표하지 않는다. 해당 자료는 연결 정확성 시험으로만 유지한다.

완료 기준:
- 잘못된 형식·물리적으로 불가능한 실제 기록이 무음 수정되지 않으며 해결 전 내보내기가 차단된다.
- 정상 반복·드문 급감속은 자동 삭제되지 않고 학생 결정과 이유가 남는다.
- 원본 보존·수정 취소·전후 건수·검증 분리 검사가 재현된다.
- 동일 분할로 후보별 지표·복잡도·주행 결과·선정 이유를 다시 계산할 수 있다.
- 최종 시험 자료와 B 코스가 설정 선정에 사용되지 않는다.
