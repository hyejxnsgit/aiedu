## 2. 교육적으로 지켜야 하는 조건

- 입력은 내 차 속도, 차체 사이 거리, 앞차 속도, 노면 상태 4개뿐이다. 시각·주행 번호·출처·모둠·운전 원칙은 모델 입력에서 제외한다.
- 목표값은 학생의 조작 의도가 아니라 바로 다음 1초 동안 실제로 변한 속도다. 안전한 정답이라는 이름을 사용하지 않는다.
- 학생 요청, 모델 제안, 한계 적용 후 실제 변화를 구분한다. 속도 상한 적용은 프로그램의 규칙이며 모델의 성취로 평가하지 않는다.
- 목표 간격, 실제 거리, 프로그램의 안전 기준 거리를 서로 다른 표시로 구분한다.
- 정상적으로 같은 상태가 반복되는 기록을 자동 중복 제거하지 않는다. 원본을 보존하며 제외 이유를 남긴다.
- 주행 전체를 학습용 또는 검증용 한쪽에 배정한다. 기본 기록도 같은 원칙을 적용한다.
- 자동 주행 기록은 학생 시범 운전 데이터에 자동 합치지 않는다. 개선용 기록은 학생이 새로 운전하여 만든다.
- 첫 모델과 개선 모델을 모두 보존한다. 같은 A 코스에서의 개선과 미공개 B 코스에서의 확인을 구분한다.
- 충돌, 기준 위반, 완주, 제한 시간 초과는 각각 기록한다. 개선 실패도 분석 가능한 결과다.

## 4. 학생 화면과 교사 준비

화면은 5개로 구분하되 현재 모둠·진행 단계·저장 상태는 항상 보인다.

1. **수업 시작:** 모둠 코드, 수업 묶음 열기, 운전 원칙 설정. 실명 입력은 요구하지 않는다.
2. **직접 운전:** 중앙에 간단한 3D 도로, 내 차와 앞차. 상단에 네 가지 입력, 옆에 현재 적용 조작과 다음 조작, 하단에 시작·일시정지·종료. 거리선 및 목표 간격 표시. 색상 외 글자·기호도 사용한다.
3. **기록과 학습:** 주행별 목록, 출처, 제외 처리, 학습/검증 배정, CSV 다운로드, Orange 진행 안내, 모델 가져오기. Tree Viewer 해석은 Orange에서 수행한다.
4. **예측과 자동 주행:** 한 장면에서 학생 선택을 먼저 저장한 후 모델값 공개. 연속 주행에서는 모델 제안, 한계 적용 이유, 실제 변화, 거리, 기준 위반을 표시한다. 운전 조작은 비활성화한다.
5. **분석과 비교:** 사건 목록에서 장면 선택, 시간 이동, 첫/개선 모델의 표 비교, B 코스 결과, 다섯 항목 보고서 저장.

다시 보기의 화면은 저장된 사실을 재생한다. 현재 모델로 과거 주행을 다시 계산하여 원본처럼 보여주지 않는다. 특정 장면에서 새 예측을 하는 기능은 별도 표시한다.

교사는 수업 전에 장비 점검, Orange 워크플로·기본 데이터 준비, 물리 설정 고정, 코스 사전 시험을 한다. 기본 버전에서는 모둠별 결과를 파일로 수합한다. 중앙 서버·실시간 대시보드는 첫 범위에 넣지 않는다.

## 5. 주행 규칙 — 제안한 초깃값

아래 수치는 실제 도로·차량의 보편적인 안전 기준이 아니다. 수업용 프로그램의 단순화한 설정이며, 1차시 담당 교사 검토와 코스 시험을 거쳐 수업용으로 확정한다.

| 항목 | 제안 | 근거·검토 |
| --- | --- | --- |
| 판단 간격 | 시뮬레이션 시간 1초 | 노션 목표값과 일치 |
| 내부 계산 간격 | 고정 0.02초 | 초당 50번 계산, 렌더링 속도와 분리 |
| 최대 가속 | +2.0 m/s², 두 노면 동일 | 노면 차이를 제동에 집중하는 초기 가정 |
| 마른 노면 최대 감속 크기 | 4.0 m/s² | 임시 실험값 |
| 젖은 노면 최대 감속 크기 | 2.5 m/s² | 같은 속도에서 더 긴 정지 거리를 관찰 |
| 속도 범위 | 마른 0–50, 젖은 0–40 km/h | 노션 기준 |
| 판정용 시간 여유 τ | 1초 | 판단 간격 1회, 사람 반응시간이라는 의미 아님 |
| 판정용 거리 여유 m | 2m | 임시 실험값 |
| 노면 변경 | 한 주행에서는 고정 | 첫 버전의 범위, 급격한 상한 변경 배제 |
| 차량 | 직진·추월 없음, 후진 없음 | 노션 범위 |

화면·CSV의 속도는 km/h, 거리 m, 시각 s. 내부 계산은 m/s·m/s². 제안 Δv(km/h)를 1초의 가속도로 바꿀 때 a_request = Δv / 3.6 / 1s.
초기 설정에서 1초의 최대 요청 범위는 가속 +7.2km/h, 감속 마른 −14.4km/h·젖은 −9.0km/h다. 실제 변화는 정지·상한 때문에 작아질 수 있다. 숫자 조작의 난이도는 학생 사용성 시험에서 확인하며 임의로 ±5에 고정하지 않는다.

### 5.1 조작과 기록 시점

초기 조작안은 '다음 1초의 희망 속도 변화량'을 슬라이더·키보드로 조정하는 방식이다. 시작 전 첫 값을 고르고 매 판단 경계에서 대기 중인 값을 확정해 1초 동안 적용한다. 구간 중 변경한 값은 다음 경계에 적용하며 화면에 '현재 적용/다음 적용'을 표시한다. 학생 사용성 검증 후 변경 가능하나, 변경하면 기록 규칙도 함께 개정한다.

1. t 시점의 네 입력을 캡처한다.
2. 직접 운전이면 학생 요청, 자동 주행이면 모델의 Δv 제안을 얻는다.
3. 노면별 가감속 한계와 속도 범위 안에서 1초 동안 움직인다. 화면 프레임이 느려져도 계산 간격을 늘리지 않는다.
4. t+1에서 실제 Δv = v(t+1) − v(t)를 계산하여 t의 입력과 같은 행에 기록한다.
5. 다음 판단에는 갱신된 속도와 거리를 사용한다.

속도가 0 또는 상한에 도달하는 소구간은 도달 시각을 구해 나누어 적분한다. 일정 가속도 구간은 x_next = x + v·dt + 0.5·a·dt², v_next = v + a·dt를 사용한다.
일시정지는 시뮬레이션 시계와 구간 진행을 모두 정지한다. 숨겨진 탭에서는 자동 일시정지하고 복귀 시 명시적으로 재개한다. 누적 벽시계 시간을 한 번에 따라잡지 않는다.

충돌·수동 종료가 1초 중간에 발생하면 사건과 부분 구간을 보존하지만 완전한 1초 목표값으로 학습 CSV에 내보내지 않는다. 남은 시간을 임의로 채우거나 1초로 환산하지 않는다.

### 5.2 거리·충돌·코스

거리 = 앞차 뒷면 위치 − 내 차 앞면 위치. 차량 길이를 포함한 동일 좌표 정의를 사용한다. 접촉 거리 0m에서 충돌을 기록하고 정지한다. 각 계산 구간 안에서 두 차의 상대 궤적의 최소 거리 및 최초 접촉 시각을 검사해 프레임 사이 통과를 놓치지 않는다.
앞차는 시각별 목표 속도와 구간 가감속이 명시된 결정적 스크립트로 움직인다. 순간적인 속도 도약은 사용하지 않는다. 내 차에 반응하여 코스가 바뀌지 않는다.
완주 기준은 코스별 고정된 내 차 도착 위치와 제한 시간으로 정의한다. 종료 사유는 completed/collision/timeout/manual_abort/error로 기록한다. 같은 틱에서 여러 사건이 겹치면 충돌을 우선하며 사건 자체는 모두 보존한다.

### 5.3 정지 거리와 프로그램 안전 기준

제동만 적용한 이론값은 d_brake = v²/(2b)다. v는 m/s, b는 해당 노면 최대 감속 크기의 양수 값이다.

판정용 초기 제안은 '앞 공간에 정지할 수 있는 여유'를 보수적으로 확보하는 기준이다. 앞으로 τ 동안 최대 가속할 가능성까지 반영한다.

```text
v_delay = v + a_max × τ
d_required = v × τ + 0.5 × a_max × τ² + v_delay² / (2 × b) + m
violation = 실제 차간거리 < d_required
```

이 식은 속도 상한을 무시한 상계여서 상한 근처에서는 여유가 크게 잡힌다. 앞차의 제동 능력·상대 속도를 반영한 실제 차량 안전 모델이 아니다. 정지 상태에서도 재가속 가능성을 포함한다. 학습용 목표값으로 쓰거나 자동으로 차를 멈추는 숨은 보정에 쓰지 않는다.
교사에게는 제동 거리와 판정용 거리의 구성 요소를 함께 보여준다. 실제 적분기로 '판단 지연 구간 → 최대 감속 → 정지'를 실행하여 계산식이 정지 거리를 과소평가하지 않는지 검사한다. 1차시에서 더 단순한 식을 선택하면 판정 정책과 코스도 함께 바꾸고 버전을 올린다.

30km/h 예시(반올림): 제동 거리 마른 약 8.68m·젖은 약 13.89m, 판정용 거리 마른 약 24.68m·젖은 약 32.69m. 이는 위 초깃값의 계산 결과이며 실측 안전 수치가 아니다.

모둠 목표 간격은 별개로 d_goal = max(모둠 정지 간격, v × 모둠 목표 초)로 제안한다. 목표 초와 정지 간격은 모둠이 정하고 판정 규칙을 바꾸지 않는다.

## 6. 데이터 계약 v0.1

CSV는 UTF-8, 소수점 '.', 단위는 열 이름에 포함한다. 화면에는 한글 설명을 대응시킨다. 내부 키는 아래 영문을 고정한다.

| 열 | 타입·단위 | Orange 역할 |
| --- | --- | --- |
| run_id | 문자열, 주행 고유 ID | 메타 |
| t_s | 수치, 구간 시작 시뮬레이션 초 | 메타 |
| source | teacher_demo / student_demo | 메타 |
| ego_speed_kmh | 수치, 조작 전 속도 | 입력 |
| gap_m | 수치, 조작 전 차체 사이 거리 | 입력 |
| lead_speed_kmh | 수치, 조작 전 앞차 속도 | 입력 |
| road | dry / wet, 범주형 | 입력 |
| actual_delta_kmh | 수치, 다음 완전한 1초의 실제 변화량 | 목표 |

CSV에 학습 역할이 자동 설정된다고 가정하지 않는다. 준비된 Orange 파일에서 열 타입·역할을 지정하고 실제 학교 Orange 버전으로 재확인한다. 원본 수치의 저장 정밀도를 유지하고 화면만 반올림한다.

수업 묶음은 다음 논리 파일로 구성한다. 압축·다운로드 UI는 구현 단계에서 결정한다.

- `session.json`: schema_version, 모둠 코드, 운전 원칙, 설정 버전, 생성 시각.
- `runs/<run_id>/meta.json`: 직접/자동 모드, 코스 ID·버전, 설정 해시, 모델 ID, 기록 출처, 시작 조건, 종료 사유.
- `runs/<run_id>/steps.jsonl`: 소구간 시각·두 차량 위치/속도·거리·판정 거리·사건. 다시 보기의 근거.
- `runs/<run_id>/intervals.csv`: 구간 입력, 요청/예측 Δv, 실제 Δv, 적용된 제한, interval_duration_s, complete_interval. 원본 보존.
- `review.csv`: run_id, t_s, include, reason, error/repeated_state/driving_choice 분류. 원본과 분리.
- `split.json`: 주행 ID별 train/validation 지정. 같은 ID 중복 배정을 거부.
- `train.csv`, `validation.csv`: 위 8열만 내보내는 Orange용 데이터. 제외 사유가 없는 무음 삭제 금지.
- `models/<model_id>/`: 원본 모델 참조, 변환 모델, 학습 데이터 해시, 버전·입력 스키마·변환기 버전, 예측 일치 검사 결과.
- `results.json`: 최소 거리, 기준 위반 시간 구간, 충돌 여부·시각, 완주 여부·시간, 종료 사유, 코스·설정·모델 참조.
- `reflection.json`: 학생 선택·예측·근거 및 윤리 토론용 다섯 항목.

학습 내보내기는 student_demo/teacher_demo 중 완전한 1초 구간만 허용한다. 자동 주행·최종 B 평가 기록은 학습 대상으로 선택할 수 없다. 검증 주행은 개선 데이터에 합쳐지지 않도록 검사한다.
로컬 임시 저장은 편의 기능으로 사용하고 명시적 수업 묶음 다운로드를 제공한다. 저장 실패·공간 부족은 표시한다. 다음 차시에 다운로드 파일을 불러와 모둠·모델·기록이 복구되어야 한다.

## 7. 모델 연결과 프로그램 구조

```text
직접 운전 화면 → 주행 계산·기록 → 학습/검증 CSV
                                      ↓
                         Orange: Tree / Tree Viewer / Predictions
                                      ↓
                            모델 변환·동일 예측 검증
                                      ↓
자동 주행 화면 ← 주행 계산 ← 네 입력을 받는 예측 모듈
       ↓
장면 다시 보기·결과 비교·모둠 보고서
```

렌더러(화면), 시뮬레이션 코어(운동·시간), 데이터 관리, 모델 예측, 결과 판정을 분리한다. 화면을 그리지 않아도 같은 코스와 모델로 같은 기록이 나와야 한다. 실제 렌더링 라이브러리와 배포 방식은 장비 시험 후 고정한다.

Orange 공식 Save Model은 모델을 pickle 기반 `.pkcls`로 저장하며, Predictions는 데이터와 학습된 모델을 받아 예측한다. 따라서 브라우저에서 저장 파일을 바로 읽을 수 있다고 가정하지 않는다.

우선 실험안: Orange 학습 환경에서 보조 내보내기 도구로 트리·입력 타입·범주 매핑·전처리를 제한된 JSON으로 추출하고 브라우저에서 예측한다. 도구는 아직 없다. 실제 트리 구조·누락값 처리·분기 비교 연산을 확인하기 전 임의 포맷으로 변환하지 않는다. 공개 웹 서버에 원본 pickle 업로드를 받는 구조는 선택하지 않는다.

연결 실험의 완료 조건:

- dry/wet, 0/속도 상한, 분기 직전·동일·직후, 학습에 없는 정상 입력을 포함한 고정 검증 묶음을 만든다.
- Orange 원본과 변환 모델의 예측을 비교한다. 수치 허용 오차 초안 1e-6 km/h, 분기 경계에서도 차이를 검사한다.
- 현재 모델 범위를 기본 회귀 Tree로 제한한다. 지원하지 않는 전처리·누락값·범주가 있으면 변환을 거부하고 이유를 표시한다.
- 원본/변환 모델과 검증 결과를 동일 model_id로 연결한다. 입력 순서·단위·범주를 확인한다.
- 실패하면 로컬 Python 예측 실행기를 대안으로 비교하고 설치·배포 부담을 기록한다. 학습 모델과 무관한 규칙 기반 운전을 대신 보여주지 않는다.

자동 주행에서 모델 로드 실패·NaN·무한대·스키마 불일치는 실행을 중단한다. 허용 범위를 넘는 유한 예측은 물리 한계로 제한하고 원래 값과 제한 이유를 모두 기록한다.
대표 장면의 트리 경로·끝마디 기록은 첫 수업용 버전에서 Orange로 확인한다. 시뮬레이터에서 정확한 트리 경로를 보여주는 기능은 별도 검증 전 약속하지 않는다.

## 8. 코스·평가·재현

- 수집 코스 2–3개: 감속, 정지·재출발, 다른 노면 조건을 포함한 약 30초 주행. 검증용 독립 주행도 별도로 확보한다.
- 비교 A: 첫 시험 후 개선에 사용 가능. 개선 전후 모델에는 동일한 초기 상태·앞차 스크립트·물리 설정을 사용한다.
- 최종 B: 첫 확인 전까지 학습·개선·학생 배포 자료에서 제외한다. 초기 버전은 교사가 별도 파일로 보관하고 마지막에 제공한다. 브라우저 코드에 포함된 숨김 버튼을 보안으로 간주하지 않는다.
- 각 코스에 버전·고정 설정·도착 위치·제한 시간을 포함한다. 원문의 A 코스 숫자는 예시이며 사전 실행 없이 확정하지 않는다.
- 코스 사전 시험은 초기 기준 충족, 최대 제동 시 정지 가능성, 적절한 기준 제어기에서 재출발·완주 가능성을 확인한다. 제어기는 교사용 코스 검사이며 학생 모델로 표시하지 않는다.
- 결과 비교는 같은 A 코스·설정일 때만 전후 비교로 표시한다. B 결과는 별도 칸에 둔다. 모델 또는 설정이 달라진 사실을 숨기지 않는다.
- 여러 모둠을 비교해도 서로 충돌하거나 간섭하지 않는 독립 실행이다. 초기는 순차 실행·기록 비교 방식이다.

## 9. 단계별 구현과 검증

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| G0 연결·장비 실험 | Orange 예측 일치 보고서, 대표 노트북 화면 실험 | 모델 변환 가능성·실행 환경 확인 |
| G1 직접 운전 | 두 차량, 조작, 원본 기록, CSV | 1초 목표값·단위·일시정지·충돌 부분 구간 검사 통과 |
| G2 전체 연결 시제품 | 모델 가져오기, 자동 주행, 결과 저장 | 한 모둠이 수집→학습→시험 전 과정을 완료 |
| G3 수업용 필수 기능 | 기록 검토, 분리, 장면 재현, 모델 비교, B·보고서 | 2–3차시 모든 활동과 산출물을 지원 |
| G4 교실 시범 운영 | 설치/시작 안내, 복구 파일, 시간 측정 보고 | 대표 학생이 각 차시 50분 이내 진행 |

G0는 개발 위험을 확인하는 선행 실험이다. 제품 기능의 구현 순서는 노션의 직접 운전 → CSV → 모델 연결 → 자동 주행 → 결과 기록을 따른다.
동시 모둠 화면, 자동 하이라이트, 분할 재생, 복잡한 환경·센서는 G4 뒤 선택 기능이다. G2만 완성된 상태를 수업 전체 완성이라고 보고하지 않는다.

필수 검증 사례:

1. 일정 가속/감속의 위치·속도가 해석식과 맞고 정지·상한 도달 시 과속·후진이 없다.
2. 젖은 노면의 정지 거리가 같은 초기 속도의 마른 노면보다 길다.
3. t 입력과 t+1 실제 변화량이 대응하고, 일시정지 중 행이 늘지 않는다.
4. 구간 중 충돌한 기록은 남지만 완전한 1초 학습행으로 사용되지 않는다.
5. 모델값/실제값 차이와 그 제한 이유가 기록되고 표시된다.
6. 분할된 train/validation의 run_id 교집합이 없고 자동 주행·B 자료가 섞이지 않는다.
7. 같은 모델·코스·설정의 반복 실행은 같은 결과이며 렌더링 프레임률에 좌우되지 않는다.
8. 다시 보기의 특정 시각과 원본 기록이 일치하고 모델 버전 교체 후에도 원본이 유지된다.
9. 브라우저 종료 후 수업 묶음 복구로 원칙·기록·모델·결과가 돌아온다.
10. 충돌 없음·기준 위반 있음·시간 초과 등 서로 다른 결과 조합이 구분된다.

성능 목표 초안: 대표 노트북의 30초 주행에서 조작·수치 표시가 끊기지 않고 보통 30fps 이상. 물리 계산의 정확성은 프레임률과 별도 검증한다. 그림자·후처리를 기본으로 끄고 저사양 2D 표시 모드를 대안으로 둔다. 이 수치는 측정 전 목표이며 호환성 보장이 아니다.

## 10. 남은 결정과 다음 작업

| 항목 | 현재 상태 | 결정 시점 |
| --- | --- | --- |
| 실제 장비·브라우저·Orange 설치 권한·인터넷 | 미확정 | G0 환경 조사 |
| 제동 성능·정지 거리 정책 | 본 문서 초깃값 제안 | G1 수치 시험 후 1차시와 공동 확정 |
| 학생 조작 방식의 직관성 | 1초 경계 적용 제안 | G1 학생 시범 조작 |
| Orange 트리 내보내기 | 미구현·가능성 검증 필요 | G0 최우선 |
| 구체적인 3D 구도 | 원문 이미지 미검토 | 화면 시제품 전 |
| 모둠 수와 교사 실행 시간 | 미확정 | G3 운영 점검 |
| B 결과 공유 전 시험 순서 | 교사 파일 제공 방식 제안 | G3 운영 점검 |

다음 개발 작업은 G0의 작은 연결 실험이다. 최소 학습 데이터와 Orange Tree 원본 예측을 준비하고, 브라우저용 변환 결과가 같은지 검증한 뒤 화면 구현 기술을 고정한다. 이 문서 단계에서는 실제 코드 실행·모델 검증이 이루어지지 않았다.
